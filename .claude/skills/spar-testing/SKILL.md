# Test Spar apps and Spar itself

The design is plan section 5 (`docs/design/testing.md`); the mechanics are the decisions "Test strategy: the app runs inside the test process" and "Test host mechanics: the generated entry point". Contract and generator rules are in `spar-contract-generation`, build rules in `spar-msbuild`.

## The test host

- **A test runs the app's own `Program.cs` in the test process:** `await using var app = await SparTestApp.StartAsync<Program>(o => o.Services(s => …), TestContext.Current.CancellationToken);`. Never launch the app's executable for anything but the black-box level, and never add test code or a test configuration file to the app.
- **How it reaches the app:** in the `Test` variant only, Spar's generator makes `Program` public and an `ISparEntryPoint`, calling the top-level method through an unsafe accessor. The test sets its session in an `AsyncLocal` and runs the entry point on a thread of its own; `SparApplication.Create` reads the session behind the feature switch `Spar.TestHost.IsSupported`, and `Run` builds the app, hands it over, and waits for disposal.
- **Overrides are ordinary DI:** `options.Services(s => s.Replace(…))` runs after the app's registrations and Spar's defaults. Fakes are objects the test keeps and inspects; `app.Services` reaches the backend directly.
- **The Browser surface** (`o.Surface = SparTestSurface.Browser`) is its own package, `src/Spar.Testing.Browser`, the only one that references the loopback host (`src/Spar.Loopback`); only end-to-end projects reference it, so `Spar.Testing` and the NativeAOT lane carry no web server (decision "Loopback transport accepted; Browser surface in its own package"). Open `app.PageUrl()` (its fragment carries the token) in a Playwright context, one shared browser per run and a context per test. `o.Page()` serves the app's own packed page, as users get it; `o.Page(folder, prefix)` serves a test page that is not the app's. Assert `app.Problems` is empty: it lists what the bridge refused or dropped and the page's CSP violations. Playwright stays out of Spar's packages. Every page evaluation gets a deadline, because a call the host dropped is never answered. A clean-console check accepts one message, Linux headless Chromium's "Unrecognized feature: 'bluetooth'" about Spar's `Permissions-Policy`, and nothing else.
- **The app's own loopback run** (`SPAR_HOST=Loopback`, M1d step 2) is not a test surface: its unit tests are `tests/Spar.Tests/LoopbackSessionTests.cs` (the record in a temporary `obj/`, the variables through a lookup function, a fixed clock) and `src/Spar.Client/test/restart.test.ts`; real runs use `docs/evidence/m1d-loopback/loopback-run.mjs` with `SPAR_LOOPBACK_BROWSER` set to its recorder, so no run opens the developer's browser, and an absolute data root (a relative `LOCALAPPDATA` is ignored). The test host's loopback names no run, so its pages never wait or reload.
- **`dotnet watch` and Hot Reload** (M1d step 3) are not a test surface either: the handler is unit-tested in `tests/Spar.Tests/BackendUpdatesTests.cs` (`BackendUpdates.Publish`, since a test process never applies updates and `UpdateApplication` does nothing there), the page side in `src/Spar.Client/test/backendUpdate.test.ts`, the restart rule in `tests/Spar.Generator.Tests/ContractShapeTests.cs`; real runs use `docs/evidence/m1d-hot-reload/watch-run.mjs` (loopback, both OSes), `WatchDesktop.cs` (Windows, `dotnet watch` on a desktop of its own, never the monitor) and `wsl.sh` (Linux, a private Xvfb). A harness edit must check it changed the file, restore every file at the end, and say how long it waits after a loopback page reloads (`--settle`; since the guard counts only reloads that get no `open`, 0.3 s is enough). `WatchDesktop.cs`'s `ctrlc` step sends a Ctrl+C to its own console, which a Development `WinExe` app it started attaches to, and `--free-console true` starts the app from a parent without one.
- **The Window surface** (`o.Surface = SparTestSurface.Window`; M1b step 8a on Windows, M1c on Linux; decisions "Step 8's shape: window tests driven by Spar's own API" and "Window tests on Windows (implementation record; choices for review)"; `docs/app-model.md` 6.12) runs the app's own `Program.cs` with its real window: the test session asks the host the app's build hands `Run` (the Test variant intercepts `Run` too) to open it (`ISparTestWindowHost`), on the test process's one UI thread, offscreen with `WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`, never activated, with the app's own packed page; on Linux (M1c step 7) on the test process's one main loop under a private Xvfb the test process starts (`Spar.Linux/Testing`). `ISparTestWindow` is host-neutral (engine requests, page script, navigation, `SparTestKey`/`SparTestPointer` input, screenshots, `ISparTestPageEvents`); each host keeps its mechanism (Windows `Spar.Windows/Testing/TestPage` over DevTools, Linux `Spar.Linux/Testing/TestPage` over WebKitGTK and `XInput` over XTEST). Drive it through `app.Page` (`SparPage`, `SparLocator`, `using static Spar.Testing.SparAssertions;`): the browser automation library's method names, Spar's own types.
  - **Locators** are role and accessible name, label, text, placeholder, alt text and title, never test ids; chains, `Filter`, `First`/`Last`/`Nth`, strict mode for actions. Each call re-resolves from the page: no element handles.
  - **The engine** is `src/Spar.Sdk/Sdk/Devtools/PageEngine.js`, plain host-neutral JavaScript embedded in `Spar.Testing` (and, for the devtools, in Development builds of apps), installed by `PageSession` with `Page.addScriptToEvaluateOnNewDocument` in the isolated world `spar-automation` before the first navigation, and called with `Runtime.callFunctionOn` in that world's context. Its unit tests are `src/Spar.Client/test/pageEngine.test.ts` (happy-dom: roles, names, queries, chains, state); layout rules (visible, stable, hit test, scroll) are checked in a real window by `tests/Spar.WindowTests`.
  - **Input is trusted** CDP `Input.*` on the host's own DevTools session, after two frames following a navigation. Never call `Page.disable` or turn the file-chooser interception off: the host's `PagePicker` relies on them. The landing check (`armPointer`/`landed`) uses capturing window listeners registered once at engine install, before page scripts; a press that misses, or a first click that misses an element still in the page (it moved between press and release), is stopped and the action retried; stability also waits for running animations on the element or an ancestor. Assert on DevTools-delivered events (`ConsoleMessages`, `PageErrors`, `Dialogs`) and `app.Problems` with a bounded wait, never right after an action. Walk text by `Rune` (`EnumerateRunes`), never by `char`: a lone surrogate becomes U+FFFD in the JSON. A character the US layout has no key for is still a key (`KeyboardLayout.Unmapped`: `key` and `text` the character, `code` empty, virtual key 0); DevTools refuses key text of more than three UTF-16 units, which one scalar value never reaches.
  - **Closing:** `app.Window.CloseAsync(options)` (`SparWindow`, public) runs the window's real close request through `ISparTestWindow.RequestCloseAsync`; the test's `Answer` reaches the host as `ICloseQuestions`, so no native dialog shows. `Automated = false` without `Answer` throws before anything is asked. `Closed` waits for the window's teardown and its leftover-renderer check.
  - **Theme:** `o.ColorScheme` is `SparColorScheme.Light` by default (`Dark`, `System`): the host fixes the window's colours and emulates `prefers-color-scheme` on the page's DevTools session. A DevTools screenshot holds the page only, not the window's own colour.
  - **Isolation:** one environment per set of browser arguments per test process under `artifacts/webview2-profiles/test-host/<run>-<pid>/`, a default-profile anchor (never InPrivate), and an InPrivate controller per window under a profile name no other open window has (`TestWindowProcess`). A window's close fails the test's cleanup when the renderer processes of its page are still running 5 s later. Each window has its own renderer (distinct profile names), so a test may end its own. Tests that send `WM_ENDSESSION` to a test window share one class (`SessionEndHostTests`): a held session end pumps the shared UI thread, and another window's session end sent meanwhile runs inside it and holds it.
  - **Linux specifics** (decision "Linux window tests (implementation record; choices for review; 2026-11-20)"; pitfalls, "Linux host"): run them in WSL with `docs/evidence/m1c-window-tests/wsl.sh window` (Xvfb on PATH, never WSLg; `SPAR_TEST_DISPLAY=session` only after asking the user). Every key and pointer event of the process goes through `XInput`'s lock, and is acknowledged by the page (the engine's `inputCount`/`inputAfter`); a character off the US layout, or a shifted one typed alone, is a spare keycode bound for it, one such stroke at a time. Windows are tiled on a 6400 × 4200 screen; a press the page never saw is clicked again. One colour scheme is open at a time (`EnterSchemeAsync`), so a test that needs two schemes at once skips on Linux. WebKit names a non-BMP key "Unidentified" and a key without a code "Unidentified": assert either. A window's renderer is the web process that appears while it loads its first page (windows take turns). The Linux host does not report the page's errors to the app's log yet.
  - **Problems:** `app.Problems` also lists every warning and error Spar logs for the app (`Spar.*` categories, through a logger provider the surface adds), so `Assert.Empty(app.Problems)` is the clean-run check; add `page.PageErrors` and console errors.
  - **Lanes:** window tests carry `[Trait("Surface", "Window")]` and browser tests `[Trait("Surface", "Browser")]`, and run as their own invocation (`--filter-trait`/`--filter-not-trait`). **`SparTestApp.StartAsync` checks the trait** (M1d step 4): a test that starts either surface without the matching value, merged by xUnit from the method, the class and the assembly, fails before anything starts, naming the trait. The values come from the teardown hook's `Before` (`SparTestCleanup.Begin(id, currentTest, surfaces)`, both lanes); an app started where no hook watches (a fixture, `SparTeardownHook=false`) is not checked, and the black box (`Surface=BlackBox`) is not checked at all. A new test of a surface gets the trait at the class, as Spar's own do; one that only checks a surface's start error (`WireShapes.Tests/SurfaceTests.cs`) carries it too. An end-to-end project joins the NativeAOT lane by removing its browser files and Playwright when `SparTestLane` is `Aot`. The page start-up tests (`StartupTests`, `StartupFrameTests`, M1d step 5) use the start-up probe (`tests/apps/StartupProbe`): its first page's start comes from the window's width (`STARTUP_PROBE_START`, one window at a time), a later page's from its address, and the explicit frame tests read the offscreen window's pixels (`WindowFrames`, `PrintWindow` with `PW_RENDERFULLCONTENT`; on Linux `X11Frames`). A test that navigates right after a page's `ready()` with a splash waits for its `ui-ready` first: it reaches the host two frames after the splash left. Spar's own window tests start with `await WindowSupport.SkipUnlessSupportedAsync()`: the first opens WindowHost's window once, and a `SparTestWindowUnavailableException` (the host's start-up check's message) skips every window test, or fails it with `CI=true`; a Windows-only mechanism skips on Linux with `WindowSupport.SkipUnlessWindows(reason)`. Spar.Sdk links the WebView2 loader into Windows test projects (`_SparWebView2Loader`).
  - **Host tests** (`tests/Spar.WindowTests`, internals through `InternalsVisibleTo`): `o.WindowPhase` sees the host's phases, `o.WaitForPage = false` returns before the page loads, and `app.Window`'s internal members post `WM_CLOSE` (`RequestCloseAsync()`), send window messages, list the renderers and read the window's native colours. At session end a test window disposes the app's services inside the hold, as an app does: read services the test needs before sending `WM_ENDSESSION`.
- **The black-box level** (level 7; M1b step 8b on Windows; decisions "Step 8b's shape: the black-box fixture" and "The black-box fixture (implementation record; choices for review)"; `docs/app-model.md` 6.13) is the only one that launches the app's executable: `await using var app = await SparBlackBox.LaunchAsync(Projects.X, o => …, token)` on the exact Production publication: a NativeAOT executable, or the CoreCLR publication the app's own project chose (M1d step 7).
  - **The build:** `<SparBlackBoxTests>true</SparBlackBoxTests>` in the test project makes the generator write `Projects` (internal, global namespace, one `SparProject` per `SparTestedApplication`, named by the app's assembly name) from `AdditionalFiles` item metadata, and target `SparBlackBoxPublish` publish each app in-process (`Restore`, then `Publish`, `SparBlackBoxBuild=true` giving it `obj/Production.BlackBox/` and `bin/Production.BlackBox/`) into the test project's `obj/…/spar-apps/<app>/`, every file but debug symbols (`*.pdb`, `*.dbg`) copied beside the tests and into their publish: a CoreCLR app's DLLs and runtime configuration, a native library beside a NativeAOT executable. The app's id, name and executable name come back with its `GetTargetFrameworks` answer (`AdditionalTargetFrameworkInfoProperty`), so no extra evaluation. `SparBlackBoxPublish=false` skips the publish (default: on, on Windows and Linux). Never in design-time builds.
  - **The run:** `LOCALAPPDATA`, `APPDATA`, `TEMP` and `TMP` into a root from `TestDataRoots.Next("black-box")`; every `WEBVIEW2_*` and `SPAR_*` variable removed; a job object with kill-on-close joined at creation (`PROC_THREAD_ATTRIBUTE_JOB_LIST`), only the output pipes inherited (`PROC_THREAD_ATTRIBUTE_HANDLE_LIST`); the hidden desktop `<station>\spar-black-box-<pid>` of `AutomationHost`, one per test process; on a CI run (the `CI` or `TF_BUILD` variable set) the runner's own desktop without activation instead, since GitHub's Windows Server runner hosts WebView2 only there (`SparBlackBox.Placement`, internal, is the run's switch: hidden desktop, shown without activation, activated, for 8c's Sandbox runner). Ready = `ReadyLine` (`<time> INFO  Spar.Host  [<run id>] ui-ready at <ms> ms`, pinned by `tests/Spar.Tests/ReadyLineTests.cs`; never change the host's phase line without it) and the main window found.
  - **UI Automation** (`BlackBox/Interop/UiAutomation.cs`, hand-declared, checked against the Windows SDK's `UIAutomationClient.h` by `tests/Spar.Tests/UiAutomationSlotTests.cs`) runs on one MTA thread per desktop (`AutomationThread`, after `SetThreadDesktop`); every element a call finds is released when it returns. Find an app's windows with `TopWindows.Of(pid)` (`EnumWindows`, no messages) and reach them by handle, never by a search from the desktop's root, which stalls on any hung app; the main window is the first whose control type is Window (the input indicator's windows are of the process too). A call that takes 10 s is abandoned with its thread. Page elements match by `UIA_AriaRolePropertyId`; native ones by control type. Every client object the fixture creates has `AutoSetFocus` off (`IUIAutomation2`): with it on, Invoke first moves the focus and the foreground, and on the hidden desktop waits about 2 s for a foreground that never comes.
  - **Platform code** sits behind `IBlackBoxProcess` and `IBlackBoxAutomation`, so the public types carry no OS annotation; `BlackBoxPlatform.IsWindows` and `IsLinux` are the analyzer's guards, and `BlackBoxPlatform.Problem` names what the machine lacks (tests skip with it through `WindowSupport.SkipUnlessBlackBox`, and fail with `CI=true`).
  - **Linux** (M1c step 7; decision "The Linux black box and SIGTERM (implementation record; choices for review)"; `BlackBox/Linux/`): the data root from `TestDataRoots.NextBlackBox()` under `artifacts/linux-homes/black-box/` holds `home`, `data` (`XDG_DATA_HOME`, `app.LocalAppData`), `config`, `cache`, `state` and `tmp` (`TMPDIR`), with `XDG_RUNTIME_DIR` at `/dev/shm/spar-bb-<root hash>-<pid>` (shared by launches on one root: the single-instance socket is there). `LinuxDesktop` starts one private Xvfb per test process from :180 (`InputDisplay`, a second one, for tests that send XTEST input; both `-noreset`, since a server that resets when its last client leaves refuses the next app's connection meanwhile) and one `dbus-daemon --session` per launch, both `KillOnParentExit`; `LinuxAppProcess` starts the app the same way and tags every process of the launch with `SPAR_BLACK_BOX_LAUNCH` (the tree is found by its environment, even after the app exited); `SIGSTOP` is `SuspendProcess`, `SIGKILL` `Kill` (exit 137). Removed from the app's environment: inherited `WEBKIT_*`, `JSC_*`, `SPAR_*`, `GTK_A11Y` (it hides the app from AT-SPI), `AT_SPI_BUS_ADDRESS`, `NO_AT_BRIDGE`, `WAYLAND_DISPLAY` and the session's launcher tokens; `o.Environment` may set `WEBKIT_*` and `JSC_*` (Spar's tests of the host's filter). `AtSpiAutomation` is AT-SPI over GDBus (`DBusClient`, `Gio.cs`, no libatspi): the accessibility bus from the launch's session bus (`org.a11y.Bus.GetAddress`, which starts at-spi2-core), the app found by pid through the bus daemon, the main window the root's first frame (role 23), dialogs role 16 or 2, walked (GTK 4's `Cache.GetItems` holds only nodes already reached), their title the app's name (substituted); page elements match WebKit's `computed-role` attribute, invoke with `DoAction(0)` (WebKit never answers `GetActions`), values through `Text.GetText`; every gone node (`UnknownMethod`, `NoReply`…) is `DBusException.IsGone`, never a failure. `EndSessionAsync` sends `SIGTERM` and waits for the exit or 5 s. Internal options for Spar's own tests: `Display`, `SessionBus`, `Wrapper` (a `bwrap` that hides a library), `DevelopmentVariables` with `SparProject.Built(path, name, appId)` for a runner's Development or WebAssembly build. Real input from the fixture is Windows Sandbox's only (a gap on Linux); Spar's Linux host tests send XTEST themselves on `LinuxDesktop.InputDisplay` (`tests/Spar.WindowTests/Linux/`). Their traits keep CI's no-skip runs honest (`eng/linux-ci/run.sh`): `Surface=BlackBox` and `App=BridgeProbe` on all, `Probe=Development` (needs the probe's Development build; only the `blackboxdev` run), `Probe=None` (runs the Notebook; only `blackbox`), `OS=Windows` (a Windows-only mechanism), `Kind=Measurement` (numbers, explicit; never in CI), `Needs=WritableProcSys` (a real namespace denial; not in a container). A new test that cannot run in one of those runs gets one of these traits, never a skip.
  - **Disposal:** an app asked to exit gets `ExitTimeout`, then it is ended; one never asked is ended at once; browser processes that outlive a clean exit by 10 s are a failure; a root that cannot be deleted is a failure; all kept through `SparTestCleanup` like `SparTestApp`'s. Spar's own tests of the fixture are `tests/Spar.WindowTests/BlackBoxFixtureTests.cs` on WindowHost's executable (`Projects.WindowHost`); `IBlackBoxProcess.SuspendProcess` makes a hung app.
- **Windows Sandbox** (M1b step 8c; decisions "Step 8c's shape: the Windows Sandbox runner" and "The Windows Sandbox runner (implementation record; choices for review)"; `docs/evidence/m1b-sandbox.md`) runs checks that need real input, focus, a clean or offline machine, or that end the session. The runner is internal to `Spar.Testing` (`Sandbox/`) until M3.
  - **Run it:** `dotnet test --project tests/Spar.SandboxTests` (in `Spar.slnx` with `<Build Project="false" />`, so never in a solution build or run; not on hosted CI, which has no Windows Sandbox). Its build publishes `Spar.WindowTests` and `Notebook.EndToEndTests` with NativeAOT into its `obj/sandbox-payloads/`; each guest test becomes a theory row of `GuestTests` named `[<job>] <guest test>`, plus a row per job. Results: `artifacts/test-results/Spar.SandboxTests/<run>/sNN/out/<stage>/` (`console.log` is xUnit's JSON reporter, streamed; `results.trx` at the end; the tests' own files under `test-results/`; the apps' logs under `artifacts/`), and `summary.txt` with each step's time. Without `wsb` every row is one skip naming why.
  - **The allow gate:** jobs in the user-session lane (windows, real input) run only with `SPAR_SANDBOX_DESKTOP=allow`, since `wsb connect`'s client window takes the host's foreground; without it their tests are listed from the payloads on the host and reported as skips naming the variable. **Agents never set it without asking the user first.** The SYSTEM lane (no connect, no window on the host) always runs.
  - **Writing a Sandbox check:** an ordinary window or black-box test with `[Trait("Sandbox", "System" | "UserSession" | "SignOut" | "CleanMachine")]` and `[Fact(Explicit = true)]`, starting with a skip unless `SandboxGuest.IsRunnerGuest` (or `IsUserSession`), so ordinary runs leave it out. The runner passes `-trait Sandbox=<lane> -explicit on`. In the guest, `SparBlackBox.Placement` is `Activated`, and the black-box window has internal real input: `locator.ClickAsync(RealMouseButton)`, `PressAsync`, `TypeAsync`, `FocusAsync`, `app.Window.ActivateAsync()` (a click on the title bar), `PressAsync(key)`, `TopLevelWindowsAsync()` (the browser's popups too), `DumpAsync()`, `dialog.ClickAsync(button)`, `OtherWindow.Show(rect)`, and `SandboxEvidence.SaveAsync` (UI Automation dump and screenshot). All of them refuse unless `SandboxGuest.EnsureUserSession` passes: the run id in `SPAR_SANDBOX_RUN`, the same id in the runner's marker `C:\spar\runner\run-id.txt`, and the user `WDAGUtilityAccount`. Never send input any other way.
  - **Folders in the guest:** the runner sets `SPAR_TEST_ARTIFACTS` (data roots and profiles, on the guest's disk) and `SPAR_TEST_RESULTS` (results, in the mapped output); tests take them through `TestArtifacts`, never by looking for the repository's files.
  - **A job that ends the session** (`SignOut`) runs in a sandbox of its own and writes what the host needs before it signs out; the runner waits `CollectAfter`, copies the job's `*.log` files from the guest's disk, and the host checks them. A sign-out terminates the test process about 130 ms after it is asked, so its app is launched with the internal `o.OutlivesTest = true` (no kill-on-close job; refused outside a runner's guest).
  - **The guest's WebView2 registration** goes stale when the host's Runtime updates (no app finds a Runtime); the runner points `Clients\…\pv` and `ClientState\…\EBWebView` at the Runtime on the guest's disk at each start, and a SYSTEM test checks it. Elements below the window's fold cannot be clicked: focus them (`FocusAsync`) and use keys. Place a second window beside the app's, never over it.
- **Page tests** (level 3; decision "Page tests: @spar/app/testing"; `docs/app-model.md` section 6.10) run the page's own code in Node under Vitest, with happy-dom for hooks and components, against `fakeSpar()` from the generated `@spar/app/testing`. The fake backend speaks the real protocol to the page's connection, so scripted values and the requests `spar.calls` returns cross the generated encoders and decoders; a command no test scripted is refused. The Notebook's are `samples/Notebook/frontend/src/*.test.tsx`, run by `npm test` after the build, which writes `@spar/app` (CI step "Page tests").
- **The app template's tests** (M1d step 4; decision "M1d step 4's shape: tests in the template") are content in `src/Spar.Templates/content/spar-app/` (`MyApp`, `MyApp.Tests`, `MyApp.EndToEndTests`, and `MyApp/frontend/src/greet.test.ts`), what every new app starts with: keep them minimal, each surface's class with its `Surface` trait, every call with `TestContext.Current.CancellationToken`, `[assembly: CaptureConsole]` in each project's `TestSettings.cs`. They are never built in place: `tests/Spar.PackageTests` packs `Spar.Templates` with the other packages, installs it into a template hive of its own (`--debug:custom-hive` under the run's folder, never the user's), makes its main consumer with `dotnet new spar-app -n Notes` (M1d step 6a; `NewAppTests` checks the files it wrote, `global.json`'s versions, the launch profiles and the solution, a new app with `--no-end-to-end-tests` whose `dotnet test` passes, and one with `--platforms` set to one OS that builds) and runs, from packages, the fast tests, their NativeAOT lane, `npm test`, and the browser, window and black-box invocations (`TemplateTests`; the Linux window and black-box ones skip on a machine without Xvfb, a D-Bus daemon and WebKitGTK 6.0). A change to them runs the package tests on both OSes (`docs/evidence/m1c-blackbox/wsl.sh … packagetests` on Linux). The frontend's `package-lock.json` is committed; regenerate it with `npm install --package-lock-only --ignore-scripts` beside a stand-in `../obj/spar/client/package.json` (`{"name":"@spar/app","version":"0.0.0"}`), and keep the Playwright version the repository's (a test checks it).
- **The template's CI workflow** (`content/spar-app/.github/workflows/ci.yml`, the M1d exit; decision "The template's CI workflow (implementation record; choices for review; 2026-11-24)") cannot run on GitHub before an app is pushed, so `WorkflowTests` proves it from packages: `Workflow.cs` reads its YAML subset (and throws outside it), the runners and steps are checked per `--platforms` and `--no-end-to-end-tests`, the action pins must equal the repository's own workflow's, and the main consumer runs each step's `run` block in order with the workflow's `env` and `RUNNER_OS` through `bash --noprofile --norc -eo pipefail` (Git for Windows' bash beside `git.exe`, never System32's, which is WSL's). It never runs the `sudo apt-get` step or the Chromium download, and never sets `CI` (the black box would then show the app's window on the desktop). A new step's `if` must be one the test reads (`runner.os == '…'`, `always()`), and a step that cannot run locally goes into its `NotRunHere` list with the reason. Keep its pins in step with `.github/workflows/ci.yml`.
- **Budgets at a slice exit** are measured by `docs/evidence/m1d-exit/win.sh` and `wsl.sh` (every line of the plan's table, M1d's no-op build and Hot Reload included). Before calling a number a regression on Windows, run the earlier commit again today (`bisect-win.sh`, from `git archive`): at the M1d exit the M1a commit itself measured twice its M1a numbers. Report a `dotnet watch` session's first Hot Reload edit apart from the later ones.
- **The spar tool** (M1d step 6b; `src/Spar.Tool`) is tested in `tests/Spar.Tool.Tests`: the machine checks against `FakeMachine` (variables, files, programs' answers, the WebView2 loader's answer, libraries, the registry; paths compared with `/`, so Linux's checks run on Windows too), never against what is installed, and nothing installed or removed; the project checks and init's edits on a copy of the template's app under `artifacts/tool-tests/` (`TemplateApp`), deleted after; init's flow with a fake npm (the scaffolder's files, an install's lockfile and record). The build identity read from real built executables is in `Spar.BuildTests` (the harness's NativeAOT executable and CoreCLR assembly, and the Notebook's published executable, inside the work tree: the repository's HEAD and state) and in `Spar.PackageTests` (`ToolTests`: the consumer's published executable and Debug build, outside any work tree: no revision). `ToolTests` also runs `dotnet tool restore` from the new app's manifest, `dotnet spar doctor --json` (no warning or error on a good machine; on Linux without WebKitGTK only those), a moved-away `node_modules` (exit 1), and `dotnet spar init frontend --framework react` with the pinned scaffolder in an app of its own, which then builds. Every tool command there gets `DOTNET_CLI_HOME` in the run's folder (`Consumer.ToolEnvironment`): `dotnet tool restore` writes the local tools' resolver cache under the CLI's home, the user's `~/.dotnet` otherwise. The host's first log line with the identity is checked on WindowHost's black-box executable (`BlackBoxFixtureTests`, both OSes).
- **The runtime choices** (M1d step 7; `docs/guide/publishing-choices.md`) are tested in `Spar.PackageTests` from the guide itself: `GuideSnippets` reads each `xml` block after its `<!-- project-snippet: name -->` marker and adds it to a new app's project, and `GuideSnippetTests` fails when the page has a block no test builds. `CoreClrTests` (`FrameworkDependentTests`, `SingleFileTests`) and `SqlClientTests` make consumers of their own (`Consumer.OnceAsync`, once per run) and run as collections of their own beside the main consumer's, so they add little to the suite's time: the publications' files, the identity `dotnet spar doctor --app` reads, the fast tests of a self-contained app, and the start to `ui-ready` through the consumer's own black-box tests plus a start-time test the run adds (`CoreClrApp.StartTimesTest`; the NativeAOT row in `TemplateTests`), with every `PATH` folder that holds a WebView2 loader removed; numbers go to `artifacts/test-results/Spar.PackageTests/measurements.txt` (`Consumer.Measure`). The SqlClient probe is the consumer's own `Program.cs` mode, with no window, run with a 30 s limit (`Tool.RunAsync`'s `limit` ends the process tree): an app started without its probe opens its window on the desktop, so never start it before checking the probe is in.
- **Typed test clients are generated** per contract in the `Test` variant (`new PagesClient(app)`). They send the same request bytes a page sends and read the outcome with the app's own serializers, so a command test covers serialization and dispatch. An infrastructure failure throws `SparCallFailedException`; a raw call is `app.InvokeAsync(contract, command, bytes, token)`, which returns the `SparOutcome`.

## Safe by default

- **One data root per app instance,** under `artifacts/test-host/<run>/app-NNN/` in this repository, from which every folder derives (the app's own folder choices included). It is deleted after the test unless `KeepData` is set. Web engine data goes under `artifacts/webview2-profiles/` or `artifacts/linux-homes/` (`AGENTS.md`).
- **External dependencies:** an app registers real resources with `AddExternal<TService, TImpl>()`; in a test host, resolving one that the test neither replaced nor allowed (`AllowExternal<T>()`) fails and names it.
- **Spar's outward services** (clipboard, credentials, shell, dialogs, tray, notifications, power) are fakes in a test host, registered behind the feature switch so Production does not contain them.
- **Spar keeps no process-wide mutable state** and never uses `Console`, environment variables or the working directory for per-app values: several apps run at once in one test process. A new static field is reviewed, and the static-state test lists the allowed ones: add it to `tests/static-state/reviewed.txt` with why it is safe (`readonly` or `writable`); the test, linked into Spar.Tests, Spar.Sdk.Tasks.Tests and WireShapes.EndToEndTests, reads the assemblies' metadata and fails on any field the list does not have.
- **A failure to stop an app never hides the test's own failure** (decision "Fixture rules: the teardown hook"): `SparTestApp.DisposeAsync` keeps it in `SparTestCleanup`, and the hook `Spar.Sdk` compiles into each test project (one file per xUnit flavour, `src/Spar.Sdk/Sdk/Testing/`) throws it after the test, so xUnit reports both; without the hook it is thrown. Keep `Spar.Testing` free of xUnit: the two lanes use different xUnit assemblies.
- **Each app instance has its own log and clock** (decision "Test host: the per-app log and the clock"): `app.Log` holds what Spar's bridge logged for that instance (every level, the newest 10,000, `app.LogDropped` for the rest), so a Browser test can check a command's failure and its correlation id; the command surface calls dispatch directly and logs nothing. `o.Time(fake)` makes the fake the app's `TimeProvider` and Spar's own; Spar registers `TimeProvider.System` by default, so app code may always inject one. The app's log file is written as a desktop run writes it (M1b step 7): `app.log` in the test's own logs folder (`app.Folders.Logs`), at the levels of `spar.Logging` and a `logging.json` in the test's data root, closed with the services and deleted with the data root unless `KeepData` (none with `spar.Logging(l => l.WithoutFile())`); `app.Log` is unchanged. The folders come from the builder (decision "Configuration stays the app's choice"): `SparApplication.Create` gives it the session's data root, so `spar.ResolveFolders()` in `Program.cs` and the `SparFolders` service are the same record, and `SparTestSession.Run` refuses folders that are not the test's rather than touch the per-user ones.

## Projects, variants and lanes

- **A test project** sets `<IsTestProject>true</IsTestProject>` and is a `Spar.Sdk` project (`<Project Sdk="Spar.Sdk">`; in this repository that SDK is the `0.0.0-source` package of `eng/source-sdk/`, which forwards to `src/Spar.Sdk/Sdk/`). It names the app it tests with `<SparTestedApplication Include="..AppApp.csproj" />`, which Spar.Sdk turns into a project reference built with `SparVariant=Test`; a plain `ProjectReference` to an app is SPAR121, and other references (libraries, the test project's or the app's) build as usual, without the variant or the test lane. Spar.Sdk adds `xunit.v3` and the test library, and turns the test-host switch on.
- **Each variant builds into `obj/<variant>/` and `bin/<variant>/`;** restore output stays in `obj/`. Never share one variant's output with another.
- **The NativeAOT lane is the same project:** `dotnet publish <tests> -c Release -p:SparTestLane=Aot` restores `xunit.v3.aot` into `obj/aot/`, builds into `bin/aot/` (its self-contained build would otherwise make the CoreCLR Release build in `bin/Production/` look self-contained) and publishes with NativeAOT. Run the published executable. Browser tests stay on CoreCLR (Playwright cannot run under NativeAOT); `xunit.v3.aot` allows no generic test methods or `params`, and prints no stack traces.
- **Results** go to `artifacts/test-results/<project>/` (decision "M1a names") in this repository and to the test project's own `obj/test-results/` in an app from packages (`SparTestResultsDirectory` overrides both; no trailing separator, which would escape the closing quote of `--results-directory "…"`); no `TestResults/` folder is left in the working directory. Every `dotnet test` run writes a TRX report there (`--report-xunit-trx`, set beside `--results-directory`), one file per run named by xUnit with the UTC time, so a failure that does not recur keeps its message and output. A published NativeAOT test executable writes one only when asked: run it with `-result-trx artifacts/test-results/<project>/aot-<UTC time>.trx`, as CI and `eng/wsl/step.sh` do (decision "Every test run keeps a TRX report").

## Dispatch, as tests see it

- **Outcomes** are a value, a declared error, or a failure with the `CallError` fields: `rejected`/`invalid-request` or `unknown-command` (`notStarted`) before the command runs; `failed`/`unknown` when it throws; `cancelled`/`stopped` only when it ended on its own call token; `response`/`serialization` (`completed`) when its result cannot be written. Nothing is retried.
- **Each call has its own DI scope** with `ISparCall` filled before the contract is resolved, and the command's `TimeoutSeconds` folded into its token.

## Verify

- Run the tests on CoreCLR and publish and run the NativeAOT lane; both must pass, with no warnings.
- **The M1 budgets** for command and browser tests are measured by `BudgetTests` in `tests/WireShapes.Tests` and `tests/WireShapes.EndToEndTests`, in Release, on both lanes for the command test (`docs/evidence/m1a-budgets.md` has the commands). They record medians and ranges to `artifacts/test-results/<project>/budgets.txt` and never assert a time.
- After a change to the test host or the generator's Test-variant output, publish the app in Release and check the production boundary: the binary contains none of `SparTestSession`, `ISparEntryPoint`, the generated clients or the fakes, nor the Window surface (`TestWindowProcess`, `ISparTestWindow`, the engine's `__sparAutomation` and its world `spar-automation`), nor the black-box fixture (`SparBlackBox`, `SparProject`, `IUIAutomationElementArray`, `spar-black-box-`; on Linux `AtSpiAutomation`, `LinuxAppProcess`, `SPAR_BLACK_BOX_LAUNCH`, `spar-bb-`) (type names are UTF-8 in the image, string literals UTF-16). `Spar.BuildTests` checks it on the Notebook and on the console harness (`tests/apps/Spar.Harness`), whose bridge is kept, so its markers live in `ProductionBoundary.cs`. The harness's NativeAOT output must equal its CoreCLR output; a change to the codec, dispatch or the serializers shows there first.
- Window tests (M1b, M1c) run as their own invocation: a native engine abort ends the whole test process. Their budget and the page API's per-action costs are recorded by `tests/Spar.WindowTests/BudgetTests.cs` to `artifacts/test-results/Spar.WindowTests/budgets.txt`. After a change to the host or the surface, check that no `msedgewebview2` process with a command line under this repository is left, and that `artifacts/webview2-profiles/test-host/` holds no root of a finished run.
- **Linux window tests on CI** run in Spar's image (`eng/linux-ci/Dockerfile`, built by the workflow's `linux-window` job). The container runs as uid 1000 with `--init`, `--shm-size=1g` and `--security-opt seccomp=unconfined`; Docker's default seccomp profile refuses bwrap's user namespaces, and AppArmor stays at Docker's profile. Reproduce a CI run locally with the commands at the top of `eng/linux-ci/run.sh` (`copy client build check window windowaot blackbox`). Mount the tree read-only; the script copies it into the container. Window-test invocations run under `eng/linux-ci/network-switch.sh`, whose FIFO (`SPAR_TEST_NETWORK_SWITCH`) lets `NetworkStatusTests` take the network away and back. Outside the switch that test skips, and with `CI=true` it fails. A test that changes process-wide or namespace-wide state (the network, the scheme) runs in a `DisableParallelization` collection of its own.
- Black-box tests (M1b step 8b) run as their own invocation (`--filter-trait "Surface=BlackBox"`) and in the NativeAOT lane. After a change to the fixture or to the host's start, check that no launched app's process is left, that `artifacts/test-host/` (Linux: `artifacts/linux-homes/black-box/`) holds no `black-box-*` root of a finished run and `/dev/shm` no `spar-bb-*` folder, and that the Production Notebook did not grow.
- The evidence for these rules is in `docs/evidence/test-host/RESULTS.md`, `docs/evidence/entry-accessor/RESULTS.md` and `docs/pitfalls.md` ("Build, MSBuild and packages", "Tooling and environment").
